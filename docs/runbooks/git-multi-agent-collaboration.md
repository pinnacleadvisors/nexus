# Runbook — Git practices for multi-agent collaboration

The goal: multiple agents (human + AI, or several AI agents in parallel) can edit this repo safely, without **stranded commits**, **mid-air collisions**, or **lost work**. Rules derived from real-world dev team practice + the specific incident classes this repo has hit.

## The single rule

> **One PR per branch. PR merged = branch terminated. New work = new branch off `origin/main`.**

Everything below is mechanical enforcement of this rule.

## Why this exists (the incident class)

May 2026 — an AI agent landed PR #223, then pushed a small follow-up rename to the same branch. PR #223 had already merged. The rename commit lived on the dead branch, invisible to reviewers, never deployed. Recovery: cherry-pick onto a fresh branch off `main`, open PR #224.

Cost: ~15 minutes of recovery + reviewer confusion. The fix is mechanical guards, not vigilance.

## Three layers of defence

| Layer | Catches | Cost to enable |
|---|---|---|
| **GitHub setting**: auto-delete head branches on merge | Most cases — second push to dead branch fails because branch doesn't exist | One command (below) |
| **Pre-push hook**: `.githooks/pre-push` queries `gh pr view <branch>`, blocks on `MERGED` | The "branch still exists but PR is done" gap | `git config core.hooksPath .githooks` |
| **Agent protocol** in [`AGENTS.md`](../../AGENTS.md) + this runbook | Discovery — humans + AI know the rule | Read it once |

All three layers in place = three independent things have to fail before a stranded commit happens.

## One-time setup

```bash
# Layer 1 — repo-side, run once by an admin
gh repo edit pinnacleadvisors/nexus --enable-auto-delete-branches

# Layer 2 — per clone (and per worktree)
git config core.hooksPath .githooks
git config --get core.hooksPath   # verify → .githooks
```

Layer 2 needs to be re-run after `git worktree add` because each worktree has its own `.git/config` by default.

## Branch lifecycle

```
  created ──push──> tracked ──open PR──> reviewed ──merge──> TERMINATED
     ↑                                                            │
     └─── new branch off origin/main ←──── new work ←─────────────┘
```

- **Created**: `git checkout -b <prefix>/<task-slug> origin/main`. Branch naming convention: `claude/<id>`, `<author>/<task>`, `feat/<topic>`, `fix/<topic>`, `chore/<topic>`. Worktree IDs (claude/fervent-wu-…) are auto-generated by the Claude Code harness.
- **Tracked**: `git push -u origin <branch>` — sets upstream so subsequent `git push` works.
- **Reviewed**: PR open, CodeQL + tsc + retry-storm green, reviewer approves.
- **Merged**: PR clicks merge → with Layer 1 on, the branch is auto-deleted from the remote.
- **Terminated**: never push more commits to this branch name. If you have work for the same logical area, branch fresh off the new `main` (which includes the merge).

## Pre-flight checks (before any unit of work)

```bash
git fetch origin main
git log --oneline HEAD..origin/main   # what's new on main since I last looked?
git rebase origin/main                # OR: git checkout -b <new-branch> origin/main
```

Why: someone else may have just landed a fix in the area you're about to touch. Reading those commits before writing your own avoids duplicate work + merge conflicts.

For long sessions: re-run `git fetch && git rebase origin/main` periodically. Don't drift more than a day from `main`.

## Conflict-resolution playbook

When `git rebase` or `git merge` hits a conflict, the resolution depends on **what the file is** — not just "pick a side":

| File class | Examples in this repo | How to resolve |
|---|---|---|
| **Generated artefacts** | `memory/molecular/INDEX.md`, `memory/molecular/.graph.json`, `.next/`, `dist/` | Accept either side, then **regenerate from source**: `node .claude/skills/molecularmemory_local/cli.mjs reindex && cli.mjs graph`. Never hand-resolve. Long term: gitignore these. |
| **Lock files** | `package-lock.json`, `bun.lockb` | Accept either side, then `npm install --package-lock-only` to regenerate. Hand-resolving conflict markers in a lockfile breaks dependency resolution. |
| **Union-of-facts** | `task_plan*.md` `## Progress` section, `memory/molecular/mocs/*` body, `docs/adr/INDEX.md` | Both sides usually have valid info — keep both. Manually merge entries chronologically. |
| **One file per item** | `memory/molecular/atoms/*.md`, `memory/molecular/entities/*.md`, `.claude/agents/<slug>.md` | By design these never collide; two agents on different items touch different files. If they DO collide, it means two agents picked the same slug — rename one. |
| **Routine code conflict** | `app/`, `lib/`, `services/` `.ts` / `.tsx` | Resolve like normal. Re-run typecheck (`npx tsc --noEmit`) + retry-storm (`npm run check:retry-storm`) before continuing. |
| **Memory files** (`memory/platform/*.md`) | Hand-curated platform docs | Prefer the version that captures the union of constraints. When in doubt: take both, then de-dupe in a follow-up commit. |

**General rule:** if you can't resolve a conflict in <5 minutes, abort (`git rebase --abort` / `git merge --abort`), re-do your work on a smaller branch off the latest `main`. Sunk-cost rebases are an anti-pattern.

## Worktree pattern (parallel agents)

When two agents need to work in parallel without colliding, use **separate worktrees**:

```bash
git worktree add ../nexus-experiment-1 -b feat/topic-a origin/main
git worktree add ../nexus-experiment-2 -b feat/topic-b origin/main
```

Each worktree has its own working tree + branch. Two Claude Code sessions in different worktrees physically cannot touch each other's files. Memory updates still share `memory/molecular/` (because they're file-per-item, by design — no collisions).

The Claude Code harness auto-spawns each session in `.claude/worktrees/<id>/` for this reason.

**Cleanup** when done:

```bash
git worktree remove ../nexus-experiment-1
# or, if the working tree is dirty (intentional preservation):
git worktree list  # shows all worktrees + paths
```

## Stranded commit — recovery procedure

Symptom: you committed + pushed to a branch whose PR has merged. The pre-push hook should have blocked you; if you bypassed or pushed before installing the hook, recover with:

```bash
# 1. Note the SHA of the stranded commit
git log --oneline -5

# 2. Sync with the new main (which has the previously-merged PR)
git fetch origin main

# 3. Fresh branch off origin/main
git checkout -b <new-branch-name> origin/main

# 4. Cherry-pick the stranded commit(s)
git cherry-pick <stranded-sha>   # repeat for each, in order

# 5. Push + open PR
git push -u origin <new-branch-name>
gh pr create --base main --title "..." --body "..."
```

The stranded commits on the dead branch can be left alone — they'll be GC'd by the remote eventually if Layer 1 (auto-delete) is enabled.

## Emergency bypass

Sometimes you genuinely need to push something the hook would block — e.g. recovering a force-pushed branch by re-pushing the lost commits. The bypass:

```bash
git push --no-verify
```

Use sparingly. Every `--no-verify` is one more case where the hook didn't save you; if it happens twice in a month, fix the underlying workflow instead.
